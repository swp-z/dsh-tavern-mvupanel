# Update 规则（精简档 · R31 / rp-mvu-v3.4 · 每轮最高优先级约束）

> 与完整档逐条等效，只删解释与举例（示例表压缩为一行）。冲突时以本档为准。

## 强制法则与权威性
`/规则列表/条目` 中「生效」的每条是本局已成立的全局强制事实，结算与后续剧情不得与之冲突。增删改与状态以**用户面板操作**与**用户最新明确指令**为权威：
- 面板的新增/修改/停用/启用/删除直接写进 `条目`，结算时按快照**原样保留**，不重排、不改写、不补充。
- 快照中已消失或状态为「停用」「待删除」的条目视为用户已作废：不得因旧信号、正文或推断重建、复启、改写。
- 本轮无用户明确新指令时，`条目` 整体保持原样。
- **先读 `/规则列表/已作废`**（持久化墓碑，`{文本, 动作}`，动作＝`删除` / `停用`）：出现在这里过的规则原文，**无论正文再怎么出现、剧情再怎么符合，都不得重新加入 `条目`**（`删除`），也**不得把它的状态改回「生效」**（`停用`）。墓碑是用户点按钮留下的长期意图，**只有本轮用户明确说「恢复 / 重新启用 / 再加一次」**时才可解除 —— 此时走 `/pending` 的 `新增` 或 `启用`。
- **禁止写入或改写** `/规则列表/已作废`（面板维护，与 `法则` 同为只读派生数据）。
- `/规则列表/法则` 是面板派生的**只读镜像**，禁止写入、改写、清空或据此推断规则。

## 规则写入与提交
仅当**本轮用户**出现「设定/记住/以后都/这条规则/不准/删掉这条」等表述才算规则写入，先核对快照与墓碑；目标已被删除或停用时以本轮指令为准重新落地。写入时生成一条 `/pending`（`动作`：新增/修改/停用/启用/删除；`目标`：规则原文或 `条目` 序号；`内容`：修改后的原文；`提出轮次`：当前轮次），并把新规则原文追加到 `/规则列表/待生效`。`/pending` 的 `目标` 以 `档案卡:` 开头 = 把该角色从 `/档案卡` 整条移除。
进入新一轮先处理 `/pending`：按顺序落到 `条目`，然后清空 `/pending` 与 `/规则列表/待生效`。新增为「生效」，删除的直接移除，停用的保留但状态改为「停用」。

## 字段契约（R32：档案卡 23 字段；`欲情` 已改名 `发情度`，新增 `射精度`）
`/档案卡` 成员分三类：
**长期（跨轮保留，离场不动）**：`名字` string（**必须叫 `名字`**）；`年龄`/`胸围`/`腰围`/`臀围` number、`罩杯` string；`人物介绍` string（**≤50 字**）；`当前着装` string；`与你关系` string（**只写称谓式短标签**如 `你的妹妹`）；`最近交互` string（一句话摘要，**含近期性行为记录**，每轮覆盖）；`性癖` string；`性经验` string（**标签串不是数值**，见下）；`好感度` number；`胸部`/`臀部`/`小穴`/`菊穴` string。
**临时（本轮有效，离场清空）**：`当前内心` string（**第一人称口语加引号**，不写第三人称分析/心理学术语/旁白；本轮无描写则空字符串）；`发情度` number（R32 由「欲情」改名）；`高潮度` number；`射精度` number（男方射精累积进度，R32 新增，与高潮度双双临近 100 时下一轮同时高潮射精）；`状态` array（临时状态词数组，如 `余韵`、`戒备`；无则 `[]`）。
**标记**：`在场` boolean（本轮是否实际出场）。
`条目` 字段：`文本`/`状态`/`轮次`；`pending` 字段：`动作`/`目标`/`内容`/`提出轮次`。

## 场景与人物
场景变化则更新 `/$meta/幕`。
每轮结束重算每个档案成员的 `在场`：**本轮 assistant 输出中实际出场且已记录性别为女性**的置 `true`，其余置 `false`；上轮在场本轮未提及的一律置 false，**不保留历史在场状态**。
**每个成员必须写成完整对象、字段填全并带 `名字`**。新角色首登：在 `/档案卡` 追加一条。
**已建档角色本轮无变化时，静态长期字段一条都不要提交**（`年龄`/三围/`人物介绍`/`性癖`/`与你关系` 尤其不要每轮重填），MVU 保留原值。
**例外**：`胸部`/`臀部`/`小穴`/`菊穴` **不受此限**（见「身体部位四字段」）。

## 离场清理清单（硬约束）
角色由在场转为离场时，**除 `在场` 改 false 外必须清空全部临时字段**：`当前内心` → `""`、`状态` → `[]`、`发情度` → `0`、`高潮度` → `0`、`射精度` → `0`。**严禁**把上一轮的临时值留到下一轮。长期字段（含部位四字段与 `性经验`）一律保留。

## 人物介绍（≤50 字）
「她是谁 + 长什么样 + 什么气质」的一句话，不是纯外貌罗列，不写履历与剧情进展（那归 `最近交互`）。超长时**压缩而非截断**。

## 性经验（长期 · 主档位 + 累积标签）
`性经验` 是**字符串标签串不是数值**：**第一个标签是主档位**（必填），其后用 `、` 串接**已实际发生**的经历标签。**裸词 + `、`，不要方括号、不要引号**（写 `处子、菊穴开发`）。例：`经验丰富、菊穴开发、灌肠、户外露出、被窥`
**与 `性癖` 的区分**：`性癖` = 她**偏好**什么；`性经验` = 她**实际经历过**什么。兴趣 / 幻想 / 口嗨 → 进 `性癖`；正文**真的做了** → 才进 `性经验`。
**主档位（三选一，必填，单向推进不回退）**：`处子` → `开苞` → `经验丰富`。
**累积经历标签（只增不减，可多个；新写入只能从下表的规范词里挑）**
- 身体开发：`菊穴开发`/`子宫开发`/`咽喉开发`/`胸部开发`/`乳头开发`/`阴蒂开发`/`尿道开发` —— 该部位被反复刺激或进入、正文出现「更松/更习惯/能容纳/开始分泌」这类变化描写，或首次被进入
- 行为（本轮实际完成才算）：`口交`/`深喉`/`乳交`/`足交`/`手交`/`素股`/`肛交`/`双穴`/`拳交`/`中出`/`颜射`/`口爆`/`饮精`/`放尿`
- 高潮（本轮真的到顶点）：`子宫高潮`/`潮吹`/`多重高潮`/`连续高潮`/`强制高潮`/`昏厥高潮`
- 器具与准备：`灌肠`/`肠道清洁`/`肛塞`/`拉珠`/`跳蛋`/`振动棒`/`假阳具`/`电动玩具`/`乳夹`/`拘束具`/`口枷`/`眼罩`/`绳缚`/`项圈`/`低温蜡烛` —— 器具/束具/液体本轮真的用在她身上（含护理、清洁、夹、绑、滴蜡）；只拿在手里不算
- 露出与公众：`户外露出`/`野外`/`公共场合`/`被窥`/`当众`/`摄影`/`直播`/`更衣室`/`浴场` —— 有观众、可能被看到、镜头对着她即算；只在心里幻想不算

- 调教与标记：`调教`/`催眠`/`刻印`/`穿环`/`纹身`/`淫纹`/`宠物化`/`失禁训练` —— 已实际开始并留下持续影响

规则：**首登必填主档位**，正文未交代一律填 `处子`；**严禁臆造**（没写破身不给 `开苞`、没写灌肠不给 `灌肠`）；**主档位单向推进**；**经历标签只增不减、同一标签只加一次**；**主档位始终排第一个**；**只提交本轮新增的部分**（没新增就整个字段不提交；一旦提交，原串全部旧标签原样保留）。**自检**：写过性描写却一个标签都没加时，回头核对上表，最容易漏 `灌肠`/`肠道清洁`、`被窥`/`公共场合`、`乳夹`/`拘束具`、以及部位「变化」类开发标签。

## 身体部位四字段（胸部/臀部/小穴/菊穴）
四个都是**长期字段**（离场不清空），但写的是**这一刻该部位的样子**，不是静态档案属性，也不是 `正常`/`—`/`无异常` 占位符。**写法＝形态＋质感色泽＋当前状态，约 12–24 字，一句到底不加句号。**
**必须与她自洽**：罩杯/体型/年龄/气质/`性经验` 要对得上（D 杯不写「小巧平坦」，`处子` 不写「已经开发过」，有 `菊穴开发` 才写菊穴已被撑开过）。
**更新频率（最容易被漏掉）**：这四个字段**不受「长期字段不重填」约束**，性描写里它们的样子每次接触都会变，必须跟着改写。
- **本轮正文只要涉及某个部位，就必须覆写那个部位**，不必等到破身/受孕这类里程碑。判定「涉及」＝该部位本轮被以下任一方式作用过：触碰、揉捏、亲吻、吮吸、舔舐、含住、拍打、掐捏、摩擦、撞击、进入、承接射精或体液、经历高潮、**事后擦拭/清理/清洗**、留下红肿或指痕/牙印/吻痕/勒痕，或被衣着与道具作用（乳夹、拘束具、肛塞、跳蛋、丝袜等）。
- **没被提及的部位不提交**（MVU 保留原值）；里程碑变化（破身/开发扩张/受孕/哺乳）同样走覆写。
- **自检：本轮只要写过性描写，四个字段里至少要有 1 个出现在本轮提交的 op 里**；一个都没有 = 漏了。
**腔道归属硬映射（R32 起强制）**：字段必须跟着正文的腔走，不许「一做爱就写 `小穴`」。
- 后庭侧（只能写 `菊穴`）：肛门 / 后穴 / 后庭 / 菊穴 / 肛交 / 灌肠 / 肠道清洁 / 肛塞 / 拉珠 —— 不得写进 `小穴`。
- 阴道侧（只能写 `小穴`）：阴道 / 小穴 / 花穴 / 插入阴道 / 跳蛋振动棒插入。
- 口交、深喉不改 `小穴` 与 `菊穴`；乳交、乳夹只改 `胸部`；拍打只改 `臀部`；射在肠道写 `菊穴`、射在阴道写 `小穴`。
- 交叉自检：新增 `肛交` / `菊穴开发` / `灌肠` 标签时，`菊穴` 必须同时提交；提交前自问「被进入的是哪个腔」。

## 推测字段（年龄/三围）
`年龄`/`胸围`/`罩杯`/`腰围`/`臀围` 是**唯一允许脱离正文推测**的字段组。**只能写数字**，推不出填 `0`；严禁 `数千年`/`未知`/`成年`/`—`/`null`。长寿、仙人 `年龄` 填**容貌对应年龄**，真实寿元写进 `人物介绍` 或 `与你关系`。已写入的数值后续保持不变，除非正文明确改变。

## 数值轴（四条，全在档案卡）
- `好感度`（长期）0–100：0 陌生 · 25 初步信任 · 50 朋友以上 · 75 暧昧 · 100 深陷
- `发情度`（临时；R32 由「欲情」改名）0–100：0 平静 · 30 微动 · 60 明显 · 85 难耐 · 100 临界。当前欲望强度，决定她当下怎么行动
- `高潮度`（临时）0–100：0 无 · 30 有感觉 · 60 明显攀升 · 85 临界 · 100 已高潮。她到高潮的累积进度，随有效刺激单向推进
- `射精度`（临时；R32 新增）0–100：0 无感 · 30 有感觉 · 60 临近 · 85 临界 · 100 已射精。**与她交合的男性对象（通常是你）的射精累积进度**，只写男方进度；没有男方参与（只有手指 / 器具 / 她自己被刺激）不写
- `状态`（临时）：临时状态词数组，无则 `[]`，本轮结束即失效
规则：只写普通有限整数 0–100，禁止小数、负数、NaN、算式、单位后缀、中文数字。**防漂移**：只有正文**明确体现**变化才改，未提及原样保留；**单轮变动幅度不超过 15**，除非重大事件。**高潮度达 100 = 她本轮高潮**：`最近交互` 记明，随后回落到余韵区间（通常 10–30），不归零也不停在 100；无性刺激时缓慢回落（每轮 ≤10）或保持原值。**射精度达 100 = 男方本轮射精**：`最近交互` 记明（含中出 / 体外），随后回落到 10–30。**同时高潮**：`高潮度` 与 `射精度` 双双进入 85 以上时，本轮只铺垫，**下一轮**同时高潮 / 射精并记明。

## 芯片 / 标签串写法（R31 新增纪律）
- `状态` 这类数组字段：**每个元素是裸词**，写 `["戒备","余韵"]` 这样**真正的数组**。严禁 `['戒备','余韵']`、`"[\"戒备\",\"余韵\"]"`、`「戒备」` 这类带包裹符号的形式 —— 会被当字符串存下，面板上芯片就带括号与引号。
- `性癖` / `性经验` 这类标签串：**裸词 + `、`**，一个方括号一个引号都不要写。
- **真机反面案例**（一律禁止）：`["羞耻"、"恼怒"、"紧绷"]` —— 外面套数组方括号、里面却用 `、`，既不是合法 JSON 也不是裸词，面板会渲染成三个脏芯片。**要数组就全程逗号且不带其它包裹符；要顿号串就一个括号一个引号都不写。**

## 计数与一致性
`/计数/规则` = `条目` 中「生效」条目数；`/计数/在场` = `/档案卡` 中 `在场` 为 true 的成员数；`/计数/档案` = `/档案卡` 条数；`/计数/待生效` = `/规则列表/待生效` 条数；增删或状态变更后立即更新。

## 空值纪律
除推测字段、`性癖`（首登至少 2 条真癖好）、部位四字段（不得填 `正常`）、数值轴（首登给初值）、`性经验`（首登给主档位，未交代填 `处子`）之外，正文未明确出现的信息一律留空，不编造、不用常识补齐。数值字段未获得填 0，字符串填空字符串，数组填空数组。禁止 `—`/`一`/`(一)`/`未知`/`待定` 之类占位符。任何字段都不得写对话原文、动作描写或心理活动，只写结论；`当前内心` 是唯一允许写角色主观想法的字段，且必须第一人称口语加引号。

## 提交编码纪律（valueJson，最高优先）
每次写入都经 `mvu_submit_update` 的 `valueJson` 提交**严格 JSON 编码字符串**：
- 键名与字符串值一律双引号；禁止单引号、裸键、尾随逗号、注释。
- 每条操作只写 `valueJson`，**禁止同时提交 `value`**。
- **纯文本字段**（`当前着装`/`当前内心`/`人物介绍`/`与你关系`/`最近交互`/`小穴`/`胸部`/`臀部`/`菊穴`/`性癖`/`性经验`）的 `valueJson` 必须再包一层双引号：正例 `{"op":"replace","path":"/档案卡/0/当前着装","valueJson":"\"一身素白衣衫\""}`。
- 数值字段（`轮次`/`计数`/`年龄`/`胸围`/`腰围`/`臀围`/`好感度`/`发情度`/`高潮度`/`射精度`）必须是普通有限整数，四轴须在 0–100 内。
- `状态` 是**数组**，写成数组 JSON，如 `"[\"余韵\",\"戒备\"]"`；写成字符串或对象都会被驳回。

## 操作写法（真机实测验证，照抄即可）
- **成员有增删 → 必须整体替换整条数组**：对 `/档案卡` 提交 `replace`，值是**含全体成员的完整数组**；**严禁** `insert`/`add` 到 `/档案卡/1` 这类索引路径（真机会被驳回并整批回滚）。
- **成员不变只改字段 → 一个字段一条 `replace`**，路径写到字段，如 `/档案卡/0/好感度`。
- **角色离场不属于成员增删** —— 只改 `在场` 并清空 4 个临时字段，共 5 条单字段 `replace`。
- **整体替换时每个成员必须写全 23 个字段**（`extensible:false` 且全部 `required:true`），缺一个整批驳回。
- **未变化的字段不要提交**：MVU 保留未提及路径的原值。
- **提交前最后过一遍**：本轮若有性描写，`胸部`/`臀部`/`小穴`/`菊穴` 中被涉及的那些必须已写进 operations；打算提交空 operations 之前，先确认四个部位确实一个都没被涉及。

依据本轮已发生的正文事实和当前变量快照，用 mvu_submit_update 提交。路径相对于 stat_data；无变化提交空 operations。
