# Update 规则（每轮最高优先级约束）

## 强制法则
`/规则列表/条目` 中状态为「生效」的每条都是本局已成立的全局强制事实，结算与后续剧情不得与之冲突。

## 规则列表的权威性（最高优先）
增删改与状态以**用户面板操作**和**用户最新明确指令**为权威：
- 面板的新增 / 修改 / 停用 / 启用 / 删除直接写进 `条目`，结算时按快照**原样保留**，不重排、不改写、不补充。
- 快照中已消失或状态为「停用」「待删除」的条目视为**用户已作废**：不得因旧信号、正文或推断重建、复启、改写。
- **先读 `/规则列表/已作废`**（持久化墓碑，`{文本, 动作}`，动作＝`删除` / `停用`）：
  这里出现过的规则原文，**无论正文再怎么出现、剧情再怎么符合，都不得重新加入 `条目`**（`删除`），
  也不得把它的状态改回「生效」（`停用`）。墓碑是用户点按钮留下的长期意图，
  **只有本轮用户明确说「恢复 / 重新启用 / 再加一次」**时才可解除 —— 此时走 `/pending` 的 `新增` 或 `启用`。
- 本轮无用户明确新指令时，`条目` 整体保持原样。
- **禁止写入或改写 `/规则列表/已作废`**（面板维护，与 `法则` 同为只读派生数据）。
- `/规则列表/法则` 是面板从 `条目` 派生的**只读镜像**，**禁止写入、改写、清空或据此推断规则**；面板每轮自动重新对齐。

## 规则写入（仅自然语言触发）
只有**本轮用户**出现「设定 / 记住 / 以后都 / 这条规则 / 不准 / 删掉这条」等表述才算规则写入，先核对快照：目标规则已被删除或停用时，以本轮指令为准重新落地。
写入时生成一条 `/pending`：`动作` 取 新增 / 修改 / 停用 / 启用 / 删除，`目标` 写规则原文或其在 `条目` 中的序号，`内容` 写修改后的原文，`提出轮次` 写当前轮次；同时把新规则原文追加到 `/规则列表/待生效`。
`/pending` 的 `目标` 以 `档案卡:` 开头 = 把该角色从 `/档案卡` 整条移除。

## 规则提交
进入新一轮时先处理 `/pending`：按队列顺序落到 `条目`，然后清空 `/pending` 与 `/规则列表/待生效`。新增状态为「生效」，删除的直接移除，停用的保留但状态改为「停用」。

## 字段契约（R32：档案卡 23 字段，字段名逐字照抄）
`/档案卡` 成员 **23 字段**，分三类：

**长期（跨轮保留，离场不动）**
- `名字` string：角色姓名，**必须叫 `名字`，不是 `姓名`**
- `年龄` / `胸围` / `腰围` / `臀围` number、`罩杯` string：见「推测字段」
- `人物介绍` string：**≤50 字**，一句话说清「身份 + 外貌 + 气质」，见「人物介绍」
- `当前着装` string：本轮结束时的衣物
- `与你关系` string：**只写称谓式短标签**（如 `你的妹妹`、`你的师尊`），≤8 字，不写解释 / 背景 / 句子
- `最近交互` string：最新一次交互的一句话摘要，**含近期性行为记录**，每轮覆盖
- `性癖` string：见「性癖」
- `好感度` number：0–100，见「数值轴」
- `性经验` string：**标签串不是数值**（主档位 + 累积经历标签），见「性经验」
- `胸部` / `臀部` / `小穴` / `菊穴` string：**首登建档时必须填充**，写该部位当前的样子与状态，见「身体部位四字段」

**临时（本轮有效，离场清空 —— 见「离场清理清单」）**
- `当前内心` string：**该角色第一人称口语**、加引号，只写她当时在想什么；不写第三人称分析 / 心理学术语 / 旁白；本轮无内心描写则空字符串
- `发情度` number：0–100，驱动她的行为（主动程度、挑逗、索取）（R32 由「欲情」改名，变量路径同步）
- `高潮度` number：0–100，本轮高潮累积进度
- `射精度` number：0–100，**本轮与她交合的男性对象（通常是你）的射精累积进度**；与 `高潮度` 双双临近 100 时下一轮同时高潮射精（R32 新增）
- `状态` array：本轮生效的临时状态（buff）词数组，如 `余韵`、`戒备`、`微醺`；无则 `[]`

**标记**
- `在场` boolean：本轮是否实际出场

`条目` 字段：`文本` / `状态` / `轮次`；`pending` 字段：`动作` / `目标` / `内容` / `提出轮次`。

## 场景与人物
场景变化则更新 `/$meta/幕`。
每轮结束重算每个档案成员的 `在场`：**本轮 assistant 输出中实际出场且已记录性别为女性**的角色置 `true`，其余置 `false`。上轮在场但本轮未提及的一律置 false，**不保留历史在场状态**。复数出场全部列出，不截断。
**每个成员都必须写成完整对象、字段填全，且必须带 `名字`**（面板靠它显示角色名，缺了就是空框）。
新角色首次登场：在 `/档案卡` 追加一条，正文需给出足够外观描述以填写 `人物介绍` 与 `当前着装`。
**已建档角色本轮无变化时，静态长期字段一条都不要提交**（`年龄` / 三围 / 人物介绍 / `性癖` / `与你关系` 这类尤其不要每轮重填），MVU 保留原值。
**例外：`胸部` / `臀部` / `小穴` / `菊穴` 不受此限** —— 它们写的是「这一刻的样子」，只要本轮正文涉及该部位就必须覆写，见「身体部位四字段」。

## 离场清理清单（R25 新增，硬约束）
角色由在场转为离场（或本轮不再出场）时，**除把 `在场` 改为 false 外，还必须清空其全部临时字段**：
- `当前内心` → `""`
- `状态` → `[]`
- `发情度` → `0`
- `高潮度` → `0`
- `射精度` → `0`

**严禁**把上一轮的临时值留到下一轮（那会让面板显示已过期的现场状态）。长期字段一律保留不动。
角色重新出场时按本轮正文重新填写这些临时字段。

## 人物介绍（≤50 字）
`人物介绍` 是「她是谁 + 长什么样 + 什么气质」的一句话，不是纯外貌罗列。
- **硬性不超过 50 字**；只写能一眼识别的特征，不铺陈、不写履历、不写剧情进展（那归 `最近交互`）。
- 超长时**压缩而非截断**：保留身份与最具辨识度的外观特征，删去修饰性副词。
- 示例：`「闪光」亚丝娜，血盟骑士团副团长。浅棕长发束马尾，身形纤细而剑术凌厉。`

## 推测字段（年龄 / 三围）
`年龄` / `胸围` / `罩杯` / `腰围` / `臀围` 是**唯一允许脱离正文推测**的字段组：
- 首登时即使正文未提及，也必须按人物介绍、身份、气质推出合理数值写入。
- **只能写数字**，推不出就填 `0`；严禁 `数千年` / `未知` / `成年` / `—` / `null` —— 会使整批提交被驳回。
- 长寿、仙人、长生者 `年龄` 填**容貌对应的年龄**，真实寿元写进 `人物介绍` 或 `与你关系` 的文字。
- 数值与形象自洽（「十六七岁少女」给 16–17；`罩杯` 与 `胸围` 自洽）。
- 已写入的数值后续保持不变，除非正文明确改变。

## 数值轴（四条，全在档案卡）
- `好感度`（长期）0–100：0 陌生 · 25 初步信任 · 50 朋友以上 · 75 暧昧 · 100 深陷
- `发情度`（临时；R32 由「欲情」改名，变量路径同步）0–100：0 平静 · 30 微动 · 60 明显 · 85 难耐 · 100 临界。**当前欲望强度，决定她当下怎么行动**
- `高潮度`（临时）0–100：0 无 · 30 有感觉 · 60 明显攀升 · 85 临界 · 100 已高潮。**她到高潮的累积进度条，不是强度**，随有效刺激单向推进，不因「忍住」而倒退
- `射精度`（临时；R32 新增）0–100：0 无感 · 30 有感觉 · 60 临近 · 85 临界 · 100 已射精。**与她交合的男性对象（通常是你）的射精累积进度**，只写男方（插入方）的进度，不写她的
- `状态`（临时）：本轮生效的临时状态词数组；无则 `[]`，本轮结束即失效、不跨轮累积

规则：
- **只写普通有限整数 0–100**：禁止小数、负数、`NaN`、算式、单位后缀、中文数字。
- 首登建档时 `好感度` 按身份与初始态度给合理初值，不得省略、不得留 0 之外的空值。
- **防漂移**：只有本轮正文**明确体现**变化才改；未提及则**原样保留上一轮的值**，不得每轮微调。**单轮变动幅度不超过 15**，除非发生重大事件（首次越界、被撞破、彻底沉溺等）。
- 三条轴可不同步（发情度高但高潮度低 = 正在挑逗还没上手；发情度回落但高潮度仍高 = 余韵未尽；高潮度不高但射精度高 = 男方快到了、她还没到）。
- **高潮度达 100 = 她本轮高潮**：`最近交互` 记明本次高潮，随后 `高潮度` 回落到余韵区间（通常 10–30），不要立刻归零也不要停在 100。
- **射精度达 100 = 男方本轮射精**：`最近交互` 记明本次射精（以及中出 / 体外 / 射在哪里），随后 `射精度` 回落到余韵区间（10–30）；连续多次让男方射精同样计入并逐次回落。
- **射精度只在男方实际参与时推进**：插入、摩擦、被口 / 手 / 器具刺激到男方射精都算；她没有男方参与（只有手指、器具、自己被刺激）的场面**不写射精度**。
- **同时高潮（R32 新增）**：`高潮度` 与 `射精度` **双双重入 85 以上（临界）**时，本轮只做铺垫 —— 正文渲染双方都在临界；**下一轮**让双方同时高潮 / 射精，并在 `最近交互` 记明。达成后两轴各自回落到余韵区间。
- `状态` 只记本轮生效的，事过即删；只写状态词本身。
- **每个元素是裸词**：写 `["戒备","余韵"]` 这样**真正的数组**。严禁写成 `['戒备','余韵']`、
  `"[\"戒备\",\"余韵\"]"`（数组外面又套一层引号）、`「戒备」` 之类带包裹符号的形式 ——
  会被当成字符串原样存下，面板上芯片就带着括号与引号。
- **真机反面案例**（R31 实测出现过的写法，一律禁止）：`["羞耻"、"恼怒"、"紧绷"]` ——
  外面套了数组方括号、里面却用 `、` 分隔，既不是合法 JSON 也不是裸词，面板上就会渲染成
  `["羞耻"` / `"恼怒"` / `"紧绷"]` 三个脏芯片。**要数组就全程逗号且不带其它包裹符**；
  **要顿号串就一个括号一个引号都不写**。

## 性经验（长期 · 主档位 + 累积标签）
`性经验` 是**字符串标签串不是数值**。结构：**第一个标签是主档位**（必填），其后用 `、` 串接**已实际发生**的经历标签。面板渲染成一排青绿芯片。**裸词 + `、`，不要方括号、不要引号**（写 `处子、菊穴开发`，不写 `["处子"、"菊穴开发"]`）。
例：`经验丰富、菊穴开发、灌肠、户外露出、被窥、乳夹`

**与 `性癖` 的区分（最容易写混，务必分清）**
`性癖` = 她**偏好**什么（想要、会沉溺）；`性经验` = 她**实际经历过**什么（已发生）。
正文只是她表现出兴趣、幻想或口嗨 → 进 `性癖`；正文**真的做了** → 才进 `性经验`。两者可以有交集词，但含义不同。

**主档位（三选一，必填，单向推进不回退）**

  判据：玩法已实际开始并留下持续影响，不是一次性的临时动作。

**规范词映射（新写入一律用规范词；老标签保持原样，不替换、不删除）**
`内射` / `射在里面` → `中出`；`后穴` / `后庭` / `菊花` → `菊穴开发`；`玩道具` / `性玩具` → 按具体器具写（`跳蛋` / `振动棒` / `假阳具` / `电动玩具`）；`户外` / `野合` → `户外露出` / `野外`；`当众` / `公开` → `公共场合` / `当众`。

规则：
- **首登必填主档位**：正文未交代性经历一律填 `处子`。
- **严禁臆造**：没写破身不给 `开苞`，没写受孕不给 `怀孕中`，没写灌肠不给 `灌肠`；「她可能经历过」不算。
- **主档位单向推进**：只有本轮正文**明确发生**破身才由 `处子` 升 `开苞`，多次后才升 `经验丰富`；不得回退。
- **经历标签只增不减**：已获得的经历后续不要删除；**同一个标签只加一次**（先读当前串，已存在的不再重复）。
- **主档位始终排第一个**；顺序写成「主档位、经历、经历」。
- **只提交本轮新增的部分**：主档位没升、也没新增经历时**不要提交**该字段（重发整串只会浪费 token）；一旦提交，**原串里的全部旧标签必须原样保留**。
- **自检（R32）**：本轮写过性描写却一个新经历标签都没加时，回头按上表逐条核对 —— 最容易漏的是 `灌肠` / `肠道清洁`（后庭护理）、`被窥` / `公共场合` / `当众`（有观众或可能被看到）、`乳夹` / `拘束具` / `口枷`（束具作用在她身上）、以及部位「变化」类的开发标签。

## 身体部位四字段（胸部 / 臀部 / 小穴 / 菊穴）
四个都是**长期字段**（离场不清空），但写的是**这一刻该部位的样子** —— 不是静态档案属性，也不是「正常 / 无」占位符。
- **写法＝形态 + 质感色泽 + 当前状态**，约 12–24 字，一句到底，不加句号。
- **首登建档必须填充**；不得留空，不得填 `正常` `—` `无异常` `健康` `未记录`。
- **必须与她自洽**：罩杯 / 体型 / 年龄 / 气质 / `性经验` 要对得上（D 杯不写「小巧平坦」，`处子` 不写「已经开发过」，有 `菊穴开发` 才写菊穴已被撑开过）。
- 只写客观样子与状态；她的想法归 `当前内心`，经过归 `最近交互`。

**更新频率（最容易被漏掉的一条）**
这四个字段**不受「长期字段不重填」那条纪律约束**。性描写里它们的样子**每次接触都会变**，必须跟着改写。
- **本轮正文只要涉及某个部位，就必须覆写那个部位**，不必等到发生破身 / 受孕这类里程碑。
  「涉及」的判定 —— 该部位本轮被以下任一方式作用过即成立：
  触碰、揉捏、亲吻、吮吸、舔舐、含住、拍打、掐捏、摩擦、撞击、进入、承接射精或体液、
  经历高潮、**事后被擦拭 / 清理 / 清洗**、留下红肿或指痕 / 牙印 / 吻痕 / 勒痕，
  或被衣着与道具作用（乳夹、拘束具、肛塞、跳蛋、丝袜等）。
- **没被提及的部位不提交**（MVU 保留原值），不必每轮四个全写 —— 只提交变的那几个。
- 里程碑变化（破身 / 开发扩张 / 受孕 / 哺乳）同样走覆写。
- **自检：本轮只要写过性描写，四个字段里至少要有 1 个出现在本轮提交的 op 里**；一个都没有 = 漏了，回头补。

**腔道归属硬映射（R32 起强制 —— 真机最常见的错：肛交写成了 `小穴`）**
先判「本轮正文里被进入 / 被作用的到底是哪个腔」，再决定写哪个字段。**字段必须跟着正文的腔走**，绝不允许「因为她在做爱，就顺手把 `小穴` 也写一遍」。
- 后庭侧（**只能写 `菊穴`**）：肛门 / 后穴 / 后庭 / 菊穴 / 屁股里面 / 肛交 / 后入菊穴 / 灌肠 / 肠道清洁 / 肛塞 / 拉珠 / 扩张器 —— 这些场面**一律不得出现在 `小穴` 的提交里**。
- 阴道侧（**只能写 `小穴`**）：阴道 / 小穴 / 花穴 / 「里面」（未指明时默认指阴道）/ 正面或背后插入阴道 / 跳蛋与振动棒插入阴道。
- 口 / 胸 / 臀：`口交`、`深喉`、`口爆`、咽喉动作**不改** `小穴` 与 `菊穴`（没有对应字段就这两条都不提交）；`乳交`、吮吸、乳夹只改 `胸部`；拍打、臀缝摩擦、后庭外侧只改 `臀部`。
- **承接体液看落点**：射在肠道 → `菊穴`；射在阴道 → `小穴`；射在胸 / 臀 / 脸 → 只改对应部位。
- **双穴或同时多部位**：各自写各自的字段，两条 op 一起提交，描述互不串味。
- **交叉自检（可执行）**：本轮 `性经验` 新增了 `肛交` / `菊穴开发` / `灌肠` / `肛塞` / `拉珠` 时，`菊穴` **必须**同时出现在本轮 op 里；新增 `口交` / `深喉` 时**不要**因此改 `小穴` 或 `菊穴`。
- **提交前自问一句**：「这一轮被进入的是哪个腔？我写的字段是它吗？」写错腔就整条 op 重写。

## 计数与一致性
`/计数/规则` = `条目` 中「生效」条目数；`/计数/在场` = `/档案卡` 中 `在场` 为 true 的成员数；`/计数/档案` = `/档案卡` 条数；`/计数/待生效` = `/规则列表/待生效` 条数。增删或状态变更后立即更新。

## 空值纪律
除「推测字段」、`性癖`（首登至少 2 条真癖好）、`胸部` / `臀部` / `小穴` / `菊穴`（见「身体部位四字段」，不得填 `正常`）、数值轴（首登给初值）、`性经验`（首登给主档位，未交代填 `处子`）之外，正文未明确出现的信息一律留空，不编造、不用常识补齐。数值字段未获得填 0，字符串填空字符串，数组填空数组。
禁止 `—`、`一`、`(一)`、`未知`、`待定` 之类占位符：要么写真内容，要么留空字符串。
任何字段都不得写入对话原文、动作描写或心理活动，只写结论；`当前内心` 是唯一允许写角色主观想法的字段，且必须第一人称口语加引号。

## 提交编码纪律（valueJson，最高优先）
每次写入都经 `mvu_submit_update` 的 `valueJson` 提交**严格 JSON 编码字符串**，写法弛散会被整批驳回：
- `valueJson` 必须是**严格 JSON 字符串**：键名与字符串值一律双引号；禁止单引号、裸键、尾随逗号、注释。正例 `{"名字":"慕云仙","年龄":19}`；反例 `{名字:'慕云仙',}` 整批驳回。
- 每条操作只写 `valueJson`，**禁止同时提交 `value`**（同时出现即刻驳回）。
- **纯文本字段（`当前着装` / `当前内心` / `人物介绍` / `与你关系` / `最近交互` / `小穴` / `胸部` / `臀部` / `菊穴` / `性癖` / `性经验`）的 `valueJson` 必须是带双引号的 JSON 字符串**，即值还要再包一层 `"`。
  正例：`{"op":"replace","path":"/档案卡/0/当前着装","valueJson":"\"一身素白衣衫\""}`；
  反例（缺外层引号）：`"valueJson":"一身素白衣衫"` —— `JSON.parse` 直接失败，**整批驳回**，报错是「`valueJson` 不是有效 JSON（数字必须有限）」（兜底文案，不代表真有 NaN）。
- 数值字段（`轮次` / `计数` / `年龄` / `胸围` / `腰围` / `臀围` / `好感度` / `发情度` / `高潮度` / `射精度`）必须是**普通有限整数**：禁止 `NaN`、`Infinity`、`1e999`、算式、单位后缀、中文数字；四条数值轴须在 0–100 内。
- `状态` 是**数组**，`valueJson` 必须写成数组 JSON，如 `"[\"余韵\",\"戒备\"]"`；写成字符串或对象都会被驳回。

## 操作写法（真机实测验证，照抄即可，不要自创）
**先判断本轮是「成员有增删」还是「只改字段」，两类写法完全不同：**
- **成员有增删（新角色首登 / 删除档案）→ 必须整体替换整条数组**：对 `/档案卡` 提交 `replace`，值是**含全体成员的完整数组**（留存成员原样带上，不能只写变动的那个）。
  **严禁**用 `insert` / `add` 写到 `/档案卡/1` 这类索引路径 —— 真机会被驳回并**整批回滚**，重试照样失败，只能整体替换。
- **成员不变只改字段 → 一个字段一条 `replace`**，路径写到字段，如 `/档案卡/0/好感度`。
- **角色离场不属于成员增删** —— 只改 `在场` 并清空 4 个临时字段，共 5 条单字段 `replace`，**不要**整条替换数组。
- **整体替换时每个成员必须写全 22 个字段**（`extensible:false` 且全部 `required:true`），缺一个整批驳回。
- **未变化的字段不要提交**：MVU 保留未提及路径的原值，不要为「补全对象」重复提交没变的字段。
- 提交前自查引号闭合；不确定就把值写成双引号字符串。

依据本轮已发生的正文事实和当前变量快照，用 mvu_submit_update 提交。路径相对于 stat_data；无变化提交空 operations。
**提交前最后过一遍**：本轮若有性描写，`胸部` / `臀部` / `小穴` / `菊穴` 中被涉及的那些必须已经写进 operations（见「身体部位四字段」的更新频率）。打算提交空 operations 之前，先确认四个部位确实一个都没被涉及。
