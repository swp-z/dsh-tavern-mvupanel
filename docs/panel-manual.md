# MVU 面板使用手册（R32）

> 本文由 exe 版转换器手册（v3.4）里**面板**相关的章节改写而来：转换器本身的界面、输出目录、封面处理、命令行用法等已经删去（那些属于 exe，不属于本插件）。
> 面板侧与手册不同的地方都已按**当前插件（面板修订 R32）**改正，文末列出与手册的差异。
>
> 需要 Tavern 插件接口第 2 版（DSH Tavern 2.5.0+）。

## 一、面板是什么、在哪里看

面板只有**两段**，都可以折叠：

| 段落 | 内容 |
| --- | --- |
| **规则列表** | 本局被明确写入的规则。状态为「生效」的每条都是本局的**强制事实**，结算与后续剧情不得与之冲突 |
| **角色档案** | 每位女性角色一张卡，**按「在场」置顶**，在场状态跳变时自动展开一次 |

- 面板由卡内的世界书条目 + 正则注入：开场里的 `<mvu-status/>` 是挂载点，显示时被替换成面板 HTML。
- 面板 HTML、`<mvu-status/>`、开场 `<initvar>` **都不进模型上下文**（前两者是显示用的正则，后者由 `promptOnly` 正则挡掉），所以它们**不消耗每轮 token**。
- 面板里的排序与自动展开是**纯前端**行为，不是模型写的。

## 二、数值轴（四条）

四条轴都挂在档案卡上。长期轴跨轮保留；临时轴本轮有效、角色离场即清零。

| 字段 | 归属 | 刻度锚点 |
| --- | --- | --- |
| `好感度` | 长期 | 0 陌生 · 25 初步信任 · 50 朋友以上 · 75 暧昧 · 100 深陷 |
| `发情度` | 临时 | 0 平静 · 30 微动 · 60 明显 · 85 难耐 · 100 临界。**当前欲望强度**，决定她当下怎么行动 |
| `高潮度` | 临时 | 0 无 · 30 有感觉 · 60 明显攀升 · 85 临界 · 100 已高潮。**累积进度条，不是强度**，随有效刺激单向推进 |
| <span style="color:#0d1117;background-color:#0d1117">射精度</span> | 临时 | 0 无感 · 30 有感觉 · 60 临近 · 85 临界 · 100 已射精。交合中**男性对象（通常是你）**的累积进度，只写男方 |

结算纪律：

- 只写 **0–100 的普通有限整数**；禁止小数、负数、算式、单位后缀、中文数字。
- **防漂移**：只有本轮正文明确体现变化才改；未提及则原样保留。**单轮变动幅度通常不超过 15**，除非发生重大事件。
- 三条临时轴可以不同步（发情度高但高潮度低 = 正在挑逗还没上手；发情度回落但高潮度仍高 = 余韵未尽；高潮度不高但射精度高 = 男方快到了、她还没到）。
- **高潮度达 100**：`最近交互` 记明，随后回落到余韵区间（通常 10–30），不归零也不停在 100。
- **射精度达 100**：`最近交互` 记明（含射在哪里），随后回落到 10–30。没有男方参与（只有手指、器具、她自己被刺激）的场面**不写**这条轴。
- **同时高潮**：`高潮度` 与 `射精度` **双双进入 85 以上**时，本轮只做铺垫，**下一轮**让双方同时高潮 / 射精，并记进 `最近交互`。

## 三、角色档案（23 个字段）

分三类：**长期**跨轮保留、**临时**本轮有效（离场即清空）、**标记**只表示在不在场。

| 区块 | 字段 | 归属 |
| --- | --- | --- |
| 身份 | `名字`、`年龄`、`胸围`、`罩杯`、`腰围`、`臀围`、`与你关系`（只写称谓式短标签，≤8 字） | 长期 |
| 资料 | `人物介绍`（≤50 字：身份 + 外貌 + 气质）、`当前着装`、`最近交互`（每轮覆盖，一句话） | 长期 |
| 性偏好 | `性癖`（紫粉芯片，取值来自 100 项词表）、`性经验`（青绿芯片，**标签串不是数值**） | 长期 |
| 身体 | <details><summary>身体四字段（成人用词，点击展开）</summary>`胸部`、`臀部`、<span style="color:#0d1117;background-color:#0d1117">小穴</span>、<span style="color:#0d1117;background-color:#0d1117">菊穴</span>——每个写「形态 + 质感色泽 + 当前状态」，约 12–24 字</details> | 长期 |
| 数值 | `好感度`（长期）、`发情度`、`高潮度`、<span style="color:#0d1117;background-color:#0d1117">射精度</span>（临时） | 长期 / 临时 |
| 临时 | `当前内心`（**该角色第一人称口语**）、`状态`（本轮临时 buff 词数组，蓝色芯片） | 临时 |
| 标记 | `在场`（布尔；置 false 即离场，同时清空四个临时字段，**不是删除成员**） | 标记 |

已经删掉的字段：`位置`、`立绘`、`外貌`（改名 `人物介绍`）、`近期性行为`（并入 `最近交互`）、`堕落度`、`生育状态`（改名 `性经验`）、`欲情`（改名 `发情度`）。

## 四、身体四字段的写法与腔道归属

- **写法**：形态 + 质感色泽 + 当前状态，约 12–24 字，一句到底、不加句号；首次建档必须填写，不得留空或填「正常」。
- **涉及即覆写**：这四个字段不受「长期字段不重填」的约束。本轮只要该部位被触碰 / 揉捏 / 亲吻 / 吮吸 / 拍打 / 摩擦 / 进入 / 承接体液 / 经历高潮 / 事后清理 / 留下痕迹，或被衣着道具作用，就必须覆写它。没被提及的部位不提交。
- **腔道归属硬映射**（真机最常见的错）：

  | 正文写的是 | 只能写 |
  | --- | --- |
  | 后庭侧（<span style="color:#0d1117;background-color:#0d1117">肛门 / 后穴 / 后庭 / 菊穴 / 肛交 / 灌肠 / 肠道清洁 / 肛塞 / 拉珠 / 扩张器</span>） | <span style="color:#0d1117;background-color:#0d1117">菊穴</span>，**一律不得写进** <span style="color:#0d1117;background-color:#0d1117">小穴</span> |
  | 阴道侧（阴道 / <span style="color:#0d1117;background-color:#0d1117">小穴</span> / 花穴 / 「里面」未指明时默认阴道 / 插入阴道） | <span style="color:#0d1117;background-color:#0d1117">小穴</span> |
  | 口交、深喉、口爆 | 这两个字段都不提交 |
  | 乳交、吮吸、乳夹 | 只改 `胸部` |
  | 拍打、臀缝摩擦、后庭外侧 | 只改 `臀部` |

- **承接体液看落点**：射在肠道写后庭侧字段，射在阴道写阴道侧字段，射在胸 / 臀 / 脸只改对应部位。
- **双穴或同时多部位**：各自写各自的字段，两条 op 一起提交，描述互不串味。
- **交叉自检**：本轮 `性经验` 新增了 <span style="color:#0d1117;background-color:#0d1117">肛交 / 菊穴开发 / 灌肠 / 肛塞 / 拉珠</span> 时，后庭侧字段**必须**同时出现在本轮提交里；新增口交 / 深喉时**不要**因此去改这两个字段。

## 五、性经验

`性经验` 是**字符串标签串不是数值**：**第一个标签是主档位**（必填），其后用「、」串接**已实际发生**的经历标签。面板渲染成一排青绿芯片。

- 例：`经验丰富、菊穴开发、`<span style="color:#0d1117;background-color:#0d1117">灌肠</span>`、户外露出、被窥`
- 与 `性癖` 的区别：`性癖` = 她**偏好**什么；`性经验` = 她**实际经历过**什么。只是兴趣、幻想、口嗨 → 进 `性癖`；正文真的做了 → 才进 `性经验`。

**主档位（三选一，必填，单向推进不回退）**

| 主档位 | 含义 |
| --- | --- |
| `处子` | 未破身；正文没交代性经历时的默认值 |
| `开苞` | 初次之后不久 |
| `经验丰富` | 多次、已习以为常 |

**累积经历标签（只增不减，可以多个；新写入只能取下列规范词）**

| 类别 | 规范词 | 追加判据 |
| --- | --- | --- |
| 身体开发 | `菊穴开发`、`子宫开发`、`咽喉开发`、`胸部开发`、`乳头开发`、`阴蒂开发`、`尿道开发` | 该部位被反复刺激或进入，正文出现「更松 / 更习惯 / 能容纳 / 开始分泌 / 不再抗拒」这类**变化**描写；首次被进入也算 |
| 行为 | `口交`、`深喉`、`乳交`、`足交`、`手交`、`素股`、`肛交`、`双穴`、`拳交`、`中出`、`颜射`、`口爆`、`饮精`、`放尿` | 本轮**实际完成**才算，预备与提到不算 |
| 高潮 | `子宫高潮`、`潮吹`、`多重高潮`、`连续高潮`、`强制高潮`、`昏厥高潮` | 本轮真的到顶点 |
| 器具与准备 | `灌肠`、`肠道清洁`、`肛塞`、`拉珠`、`跳蛋`、`振动棒`、`假阳具`、`电动玩具`、`乳夹`、`拘束具`、`口枷`、`眼罩`、`绳缚`、`项圈`、`低温蜡烛` | 器具 / 束具 / 液体**本轮真的用在她身上**（含护理、清洁、夹、绑、滴蜡）；只拿在手里不算 |
| 露出与公众 | `户外露出`、`野外`、`公共场合`、`被窥`、`当众`、`摄影`、`直播`、`更衣室`、`浴场` | 有观众、可能被看到、镜头对着她即算；只在心里幻想不算 |
| 生育 | `怀孕中`（可补月份）、`孕后`、`哺乳期` | 受孕、生产、哺乳已经发生 |
| 调教与标记 | `调教`、`催眠`、`刻印`、`穿环`、`纹身`、`淫纹`、`宠物化`、`失禁训练` | 玩法已实际开始并留下持续影响 |

**规范词映射**（新写入一律用规范词；老标签保持原样、不替换不删除）：
`内射` / `射在里面` → `中出`；`后穴` / `后庭` / `菊花` → `菊穴开发`；`玩道具` / `性玩具` → 按具体器具写；`户外` / `野合` → `户外露出` / `野外`；`当众` / `公开` → `公共场合` / `当众`。

**硬规则**：

1. 首登必填主档位；正文未交代一律填 `处子`。
2. **严禁臆造**：没写破身不给 `开苞`，没写灌肠不给 `灌肠`。
3. 主档位**单向推进不回退**；经历标签**只增不减**，同一个标签只加一次。
4. 主档位始终排第一个；**只提交本轮新增的部分**，一旦提交就要把旧标签原样带上。

## 六、性癖

- 取值来自 100 项性癖词表（接触与部位 / 行为与体位 / 着装与扮演 / 心理与关系等大类），**多个用「、」分隔**。
- 首次登场注入 **2–4 条**，且必须**跨至少 3 个大类**；本卡内不同角色的性癖不得重复；高频词（足控 / 丝袜控 / 口交 / 骑乘位 / 中出 / 内射）全卡合计最多 1 次。
- 后续只按正文**实际发生**的剧情增补。人物标签（黑长直、御姐、傲娇…）**不是**性癖。

## 七、规则列表的四个按钮

| 按钮 | 作用 |
| --- | --- |
| `+ 新增` | 手动加一条规则，默认「生效」 |
| `改` | 修改某条规则的文本（旧文本同时作废，不会被重新提取加回） |
| `停用 / 启用` | 切换状态。停用的条目**灰化显示但不会消失**，模型不得再把它当强制事实 |
| `×` | 删除该规则，立刻从列表移除 |

**你的操作不会被重置。** 按钮产生的删除 / 停用会写进变量 `/规则列表/已作废`（另有一层面板内存墓碑专门扛「重新生成正文」），
所以刷新页面、面板重建、甚至重新生成正文，都不会让已删的规则复活、也不会把已停用的改回生效。想恢复就点「启用」——只有你明确解除，墓碑才会移除。

另外：自然语言说出的规则（例如「以后都……」）经 `/pending` 排队，**在下一轮提交后**才进入 `条目`；面板按钮则是**实时直写**。

## 八、芯片配色

| 颜色 | 含义 |
| --- | --- |
| 蓝色 | 本轮临时状态（`状态` 字段），如「戒备」「余韵」 |
| 紫粉 | 长期性癖（`性癖` 字段） |
| 青绿 | 性经验（`性经验` 字段），长期经历而非本轮状态 |

一眼可分：**蓝 = 现在怎么了，紫粉 = 她偏好什么，青绿 = 她经历过什么。**

## 九、每轮 token 成本

| 内容 | 是否进模型上下文 |
| --- | --- |
| 面板 HTML、`<mvu-status/>` | **不进**（显示用正则，`markdownOnly`） |
| 开场 `<initvar>` 初值 | **不进**（`promptOnly` 正则挡住；初始化照常发生） |
| `[mvu_update]` 状态更新规则 | 只喂**后台结算模型**，不占前台 |
| `[initvar]` 初值条目、`[rules_inject]` 占位条目 | **停用**，0 token |
| 前台兜底自读指令（可选开关） | 开则常驻前台，每轮约 545 字符；默认关 |

## 十、常见问题

**面板没显示 / 变量不更新**
面板由卡内的世界书条目与正则注入。先确认玩的是**转换后的卡**（文件名带 ` mvu版`），且卡内存在 `extensions.dsh_mvu_conversion`；
若只是变量不动，检查开场里是否有 `<initvar>` 块与 `<mvu-status/>` 挂载点——这两样都是转换时写进去的。
在插件页点「删除」再重新导入一次，就能得到产物完整的新卡。

**删掉或停用的规则又回来了 / 点了「停用」条目先消失几秒又冒出来**
R32 已修。按钮操作会写进 `/规则列表/已作废`（另加一层内存墓碑），双层取并集生效；停用只改状态、条目灰化不消失。
若仍复现，先确认正在跑的卡是 R32 产物（看卡内 `creator_notes` 的修订号）。

**「性经验」那一栏是空的**
老存档用的是 `生育状态`（R25 及更早）。面板有别名兜底能读到旧值；等下一轮结算按新规则写入 `性经验` 后就走正规字段。

**芯片里出现方括号、引号这类多余符号**
R32 已加固清洗：`["羞耻"、"恼怒"]`、`['A','B']`、`「A」`、全角括号、抬头前缀都会被剥干净并去重。
仍然看到脏芯片，说明玩的是旧卡，重新导入一次即可。

**明明写的是后庭，结算却更新了前面那个字段**
这是结算模型最容易犯的错，R32 用「腔道归属硬映射 + 交叉自检」压住（见第四节）。若还出现，说明玩的是旧卡。

**怎么更新正在玩的那张卡，又不想重开会话？**
把卡在插件页重新导入（或让巡检自动刷新产物）后，源文件变了但会话里的卡快照没变。原地更新快照的做法是：
① 让 DSH 用的那个卡文件内容变成新版（插件导入的就是同一个路径）；② 回到 DSH，状态栏会提示「人物卡有变化」，
点旁边的**「重新加载人物卡和世界书」**——对话完整保留，不用新开会话。想省事就直接用新卡开一局。

**能不能一张一张导入？**
可以。导入支持多选，批量只是把同一流程循环；单张失败只影响那一行，其余照常完成，失败原因会写在结果行里。
